# 5 分钟答辩演示脚本

主线使用离线模式，真实 Hermes 不作为演示前提。以下人物、制度、金额和时间均为虚构示例。

## 演示前检查清单

- 本地：运行 `npm ci`，再运行 `npm run demo`，保持该终端开启。准备备用 Pages 链接：https://alpszz-cc.github.io/tuanxue-assistant/ 。
- 管理端直达：http://localhost:4173/#/admin/dashboard?as=admin_wang
- 学生端直达：http://localhost:4173/#/student/chat?as=stu001
- 使用备用 Pages 时：管理 https://alpszz-cc.github.io/tuanxue-assistant/#/admin/dashboard?as=admin_wang ，学生 https://alpszz-cc.github.io/tuanxue-assistant/#/student/chat?as=stu001 。
- 打开管理端“设置”，先重置全部演示数据并确认，检查模式为“离线演示”。
- 同一浏览器两个窗口并排，左学生、右管理；不要用不同浏览器或隐身与普通窗口混搭，否则 localStorage 不共享。1366 屏幕可给管理端更多宽度；浏览器缩放保持清晰可读。
- 学生页面右上角应为“离线演示”；准备 `hermes/skills/tuanxue-assistant/references/doc-zongce.md` 作为上传样例。
- 一遍走完后，正式上台前再次重置，避免已读、工单和已沉淀资料影响顺序。

## 0:00—0:30 开场与概览

**点哪里：** 右侧工作台，依次指向咨询数、AI 解答率、待处理工单和高频问题；悬停指标旁图标可看统计口径。

**说什么：** “团学事务中，重复制度咨询与群聊转发占用大量时间。学生可以自己查制度，管理端接住需要人工核实的问题，并把老师的答复沉淀成可复用知识。”

**出问题怎么办：** 页面未进身份就用上方直达链接重新打开；页面排版太窄就扩大管理窗口，导航会自动收起。

## 0:30—1:10 导入资料

**点哪里：** 管理端“知识库”→“上传资料”→选择 doc-zongce.md →把标题核对为“××学院学生综合素质测评实施细则（示例）”、分类选“综测评奖”→“保存资料”，确认列表新增。

**说什么：** “老师只需导入现成制度文件，不需要整理成数据库。支持纯文本、Markdown 和 Word，资料在同浏览器两个窗口中自动同步。”

**出问题怎么办：** 文件选择受阻时，点“新增资料”，从已有示例中复制正文、选择分类后保存；内置示例制度本身也足以完成后续问答。

## 1:10—1:50 带出处的制度问答

**点哪里：** 学生端“问答”→点击推荐问题“志愿服务在综测里怎么加分”→展开回答下方“参考资料”。

**说什么：** “系统依据制度第二条回答：每满4小时0.5分，学年最高3分。答案下方可以核对原文，不是凭印象给政策结论。”

**出问题怎么办：** 等逐字显示结束再操作。若之前切换到智能体导致变慢，在管理端设置切回离线；已导入制度可直接检索，不需要网络。

## 1:50—3:15 转人工、回复与知识沉淀

**点哪里：** 学生输入“食堂几点开门”→看到已转交提示；管理端“咨询汇总”找到同一问题→“回复”，填入“食堂每天早上七点开门，具体以现场通知为准。（演示答复）”→“发送回复”。学生端切“我的咨询”，展开“王老师的回复”。管理端对这条工单点击“沉淀到知识库”。学生回“问答”再次输入相同问题。

**说什么：** “资料没有写的内容会转人工，不附无关依据猜答案。老师回复后，学生会收到新回复角标。经过确认的回复可以沉淀，再问相同问题就能直接答上，出处会显示‘王老师的答复（已沉淀至知识库）’。”

**出问题怎么办：** 若一开始就直接答出食堂时间，说明之前的演示资料没重置；可换一个资料外问题，或重置后重演。工单不出现时确认两个窗口同源、同一浏览器；刷新保留各自身份。

## 3:15—3:55 发布通知与已读回执

**点哪里：** 管理端“通知发布”，标题“明日团学工作说明会”，正文填演示说明，类型“通知”，对象“全体学生”→“发布通知”；学生端“通知”打开新通知。管理端列表观察已读从0/2变为1/2。

**说什么：** “同一条消息可以指定全体、学生会干部或2024级。通知直接到达对应学生，并能看到已读进度，减少层层转发。”

**出问题怎么办：** 已读角标不是零很正常，初始数据有旧通知已读记录。核对刚发布的标题那一行，不要用全站角标代替这条通知的回执。

## 3:55—4:45 从群聊整理通知

**点哪里：** “从聊天记录生成通知”→“填入示例”→“整理成通知”。展示最终地点、参加对象、待办和截止时间→“填入发布表单”→核对对象已为“学生会干部”→“发布通知”。学生端查看新通知。

**说什么：** “这段群聊有老师、主席、干事和外院同学，且修改了两次安排。系统整理最终意见：地点为图书馆报告厅、对象限本院学生会干部，名单10月17日17点前提交。发布前由管理者核对。”

**出问题怎么办：** 离线只对内置示例提供确定结果，点击‘填入示例’可恢复；任意新聊天需要兼容接口可用。若生成失败，仍可把要点手动填入通知表单。

## 4:45—5:00 收束

**点哪里：** 回到工作台，展示动态变化。

**说什么：** “核心闭环是制度自助问答、无法回答时接住咨询、老师回复沉淀、通知按对象直达。离线模式确保答辩稳定，兼容接入层可在真实环境继续连接 Hermes。”

**出问题怎么办：** 本地终端关闭时重启 `npm run demo`；备用 Pages 页面也可完整演示离线主线，但数据属于 Pages 自己的浏览器存储，需要重新重置和打开两个同源窗口。

## 可选加演：兼容接口

在正式主线之外进行，不以此替代离线主线。配置 `.env.local` 后重启 `npm run demo`，管理端设置切“智能体”、测试连接，再问志愿服务问题；展示查阅进度和流式输出。未配置服务时，展示清晰的失败原因和离线降级提示即可。`mock-llm` 仅作开发验收，不用于正式答辩冒充真实智能体。真实 Hermes setup 必须在 SSH 终端人工审核运行。
