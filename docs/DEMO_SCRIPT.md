# 武汉大学哲学学院团学事务助手 · 线上共享屏幕演示

以现场发布的赛事通知贯穿全部功能，约5分钟。使用一个屏幕共享给腾讯会议，在同一屏幕上把两个浏览器窗口并排：左侧学生端，右侧管理端。主线使用离线演示；真实智能体不作为成功前提。

## 演示前检查清单

- 运行 `npm ci`、`npm run demo`，保持终端开启。备用站点：https://alpszz-cc.github.io/tuanxue-assistant/ 。
- 管理端直达：http://localhost:4173/#/admin/dashboard?as=admin_wang
- 学生端直达：http://localhost:4173/#/student/chat?as=stu001
- Pages 对应管理链接：https://alpszz-cc.github.io/tuanxue-assistant/#/admin/dashboard?as=admin_wang ，学生链接：https://alpszz-cc.github.io/tuanxue-assistant/#/student/chat?as=stu001 。
- 在管理端“设置”重置演示数据，确认模式为“离线演示”。两窗口必须同一浏览器、同一站点；不要混用本地与 Pages、普通与隐身窗口。
- 选择腾讯会议共享整个屏幕；两个浏览器窗口并排，给管理端更多宽度，学生端保持手机版式。先关闭无关消息提醒。
- 现场发布前，确认知识库中没有本次赛事通知。内置制度仍为“××学院（示例）”；赛事通知按用户提供的原文展示，不自行改写时间。

## 1. 发布前问不到：0:00—0:40

**点哪里：** 学生端直接输入“评审PPT什么时候交”。右侧管理端打开工作台，观察待处理转人工数增加1。

**说什么：** “这是武汉大学哲学学院团学事务助手。当前知识库尚未收到这份赛事通知，所以系统不猜截止时间，而是转交老师。”

**出问题怎么办：** 如果直接答出了日期，说明上一轮演示没有重置。到设置重置后重新提问；若窗口不同步，检查两边是否同源、同一浏览器。

## 2. 现场发布与通知同步：0:40—1:30

**点哪里：** 管理端“通知发布”→“填入示例通知”。确认标题为首届“数智珞珈・青春揭榜”哲学学院榜题评审通知；对象全体学生、置顶；“同步到知识库（学生可直接提问）”保持打开→“发布通知”。学生切换“通知”，未读角标增加1，打开新通知；右侧已发布列表已读数从0/2变1/2。

**说什么：** “老师发布一份通知，就同时完成消息送达和知识更新。学生不必从群聊翻找文件，管理端还能看到阅读回执。”

**出问题怎么办：** 不要仅看全站未读总数，它包含旧通知；核对刚发布标题的那一行。确认同步开关打开，否则这份通知只送达、不进入问答知识库。

## 3. 发布后马上能问：1:30—2:10

**点哪里：** 学生回“问答”，再次问“评审PPT什么时候交”，再问“报名表发到哪个邮箱”，展开参考资料。

**说什么：** “现在系统能准确给出10月18日12:00，出处是通知第二节。报名表的邮箱则引用第一节，不会把一整节文字倒出来，也不会引用奖助制度。”

**出问题怎么办：** 到知识库确认来源为“通知同步”。若没有该文档，重新发布并打开同步开关；如果仍处于智能体模式，切回离线再问。

## 4. 回复最初的咨询：2:10—2:45

**点哪里：** 管理端“咨询汇总”，找到第1步的“评审PPT什么时候交”工单→“回复”，填“通知已发布，请查看通知第二节”→发送。学生切“我的咨询”，展开王老师的新回复。

**说什么：** “发布资料并不会丢掉之前的咨询。老师仍可回到最早的工单，告诉学生去哪里查看，新回复也有角标提醒。”

**出问题怎么办：** 按待处理状态筛选，确认找的是第1步工单。查看回复需要在学生端展开；老师已经回复但角标没有变化时，确认没有在另一窗口先读过。

## 5. 资料外问题与老师答复沉淀：2:45—3:45

**点哪里：** 学生问“评委都有哪些老师”，看到转人工。管理端回复“演示说明：评委由学院另行通知，请以正式评审通知为准。”→发送→点击“沉淀到知识库”。学生再问同一问题。

**说什么：** “这份通知没有给出评委名单，系统不能根据学院名称编造老师。经老师确认的答复可以沉淀，后续再问会直接引用‘王老师的答复（已沉淀至知识库）’。”

**出问题怎么办：** 先回复才能沉淀；按钮变为‘已沉淀’说明成功。不要在演示时虚构真实评委姓名。学生问法保持一致，方便展示前后变化。

## 6. 加分项：群聊整理通知：3:45—4:35

**点哪里：** 通知发布→“从聊天记录生成通知”→“填入示例”→“整理成通知”。展示最终地点、对象、待办与截止时间→“填入发布表单”→核对对象为学生会干部→“发布通知”。

**说什么：** “群聊里有多方沟通和修改意见，系统整理最后确认的信息，管理者核对后发布。离线主线对内置示例给出确定结果，任意新聊天需要接通兼容接口。”

**出问题怎么办：** 使用内置示例，避免将未知群聊套入固定结果。若生成失败，点击填入示例重试，或手动把要点填入通知表单。

## 7. 回到工作台收尾：4:35—5:00

**点哪里：** 管理端“工作台”，展示咨询数、待处理数、已读率与高频问题，悬停指标图标可看统计口径。

**说什么：** “一份通知串起了‘发布前不猜、发布即入库、学生准确问答、人工回复和知识沉淀’。猫头鹰与对话气泡是本项目原创标识，虚构制度保留示例名义，真实信息始终以学院发布内容为准。”

**出问题怎么办：** 本地服务中断时重新运行 `npm run demo`；使用 Pages 备用站时重新开两个同源窗口并重置，不能沿用本地站的业务数据。

## 可选加演
